# StockFlow

Small warehouse app: products, stock adjustments, sales orders that consume stock.
Postgres → Go API → React (Vite, TypeScript strict).

## Run it (≈2 minutes)

### Everything in Docker

```bash
docker compose up --build
```

- UI: http://localhost:5173 (nginx serves the build and proxies `/api` to the backend)
- API: http://localhost:8080
- Postgres: localhost:5432 (user/password/db: `stockflow`)

Migrations and seed (`backend/migrations/001_schema.sql`, `002_seed.sql`) run on first start of an empty volume. To reset: `docker compose down -v`. If you pulled a version with new tables or columns (`audit_log`, `products.min_stock`, `sales_orders.idempotency_hash`), reset the volume, or apply the `ALTER`s by hand.

### Local dev (hot reload)

```bash
docker compose up -d db                      # 1. database
cd backend && go run ./cmd/server            # 2. API on :8080 (DATABASE_URL overrides default)
cd frontend && npm install && npm run dev    # 3. UI on :5173
```

Vite proxies `/api` → `http://localhost:8080` (`frontend/vite.config.ts`, override with `API_PROXY_TARGET`), so no CORS is needed in dev. The API also sends permissive CORS headers so it works from any origin. Vite 8 needs Node ≥ 20.19 / 22.12.

### Tests

```bash
cd frontend && npm test                      # Vitest: validation + formatting
# backend needs a scratch DB (the test drops and recreates the schema!)
docker compose exec db createdb -U stockflow stockflow_test
cd backend && TEST_DATABASE_URL='postgres://stockflow:stockflow@localhost:5432/stockflow_test?sslmode=disable' go test -race ./...
```

Backend tests cover: insufficient stock rejected with nothing written (orders, items, movements, other items' stock), happy path (stock + movement + server total), validation cases, cancel restores once, delete-with-history, **50 concurrent orders vs 20 units** (exactly 20 win, stock ends 0), opposite-order multi-item concurrency (no deadlock/oversell), and idempotency under 8 concurrent retries. Without `TEST_DATABASE_URL` they skip.

Handler tests (`internal/httpapi/api_test.go`) need no database: they use `internal/httpapi/mocks`, generated by [mockery](https://github.com/vektra/mockery) from the `httpapi.Store` interface. After changing that interface, regenerate with:

```bash
go install github.com/vektra/mockery/v2@v2.53.3
cd backend && mockery        # reads .mockery.yaml
```

## API

| Method | Path | Notes |
|---|---|---|
| GET | `/api/products` | `search`, `page`, `limit`, `status` (extension: `active`/`inactive`/`low`); each item has `last_movement_at` and `min_stock`. Add `after=<id>` (`0` to start) for keyset pagination: no OFFSET, response carries `next_cursor` |
| POST | `/api/products` | 201; 400 validation; 409 `DUPLICATE_SKU`; optional `min_stock` (default 10) |
| POST | `/api/products/bulk` | extra: `{"products":[...]}`, 1 to 500 rows, all-or-nothing; 400 with `products[i].field`, 409 with the duplicate row |
| PUT | `/api/products/{id}` | 404 when missing |
| DELETE | `/api/products/{id}` | 204; 409 `PRODUCT_HAS_HISTORY` |
| POST | `/api/products/{id}/stock` | 201 `{product, movement}`; 409 `INSUFFICIENT_STOCK` with `available` |
| GET | `/api/products/{id}/movements` | newest first, `{data}` |
| POST | `/api/orders` | 201; optional `Idempotency-Key` header (422 `IDEMPOTENCY_KEY_REUSED` if the key was used with a different body); 400/409 as below |
| GET | `/api/orders` | extra: recent orders (`limit`) |
| GET | `/api/orders/{id}` | order + items + status + total |
| POST | `/api/orders/{id}/cancel` | restores stock; 409 `ORDER_ALREADY_CANCELLED` |
| GET | `/api/summary` | extra: totals for the summary cards |
| GET | `/api/reports/daily-sales?date=` | bonus; `YYYY-MM-DD`, Asia/Jakarta day |
| GET | `/api/audit` | extra: audit trail, newest first; `entity=product\|order`, `entity_id`, `page`, `limit` |

### curl examples

```bash
curl 'localhost:8080/api/products?search=mouse&page=1&limit=10&status=low'   # status: active|inactive|low (extension)
curl -XPOST localhost:8080/api/products -d '{"sku":"XX-1","name":"Thing","price":10000}'
curl -XPUT  localhost:8080/api/products/1 -d '{"sku":"KB-001","name":"Keyboard","price":900000}'
curl -XDELETE localhost:8080/api/products/1                                  # 409 PRODUCT_HAS_HISTORY
curl -XPOST localhost:8080/api/products/1/stock -d '{"type":"out","qty":5,"note":"damaged"}'
curl localhost:8080/api/products/1/movements
curl -XPOST localhost:8080/api/orders -H 'Idempotency-Key: abc-123' \
  -d '{"customer":"Budi","items":[{"sku":"KB-001","qty":2},{"sku":"MS-002","qty":1}]}'
curl localhost:8080/api/orders/1
curl -XPOST localhost:8080/api/orders/1/cancel                               # 409 ORDER_ALREADY_CANCELLED if repeated
curl localhost:8080/api/summary                                              # extra: summary cards
curl 'localhost:8080/api/reports/daily-sales?date=2026-10-27'                # bonus
curl localhost:8080/api/orders                                               # extra: recent orders
```

Errors always look like `{"error":{"code","message", ...}}`:
`VALIDATION_ERROR` 400 (`details:[{field,message}]`, fields like `items[1].qty`), `INSUFFICIENT_STOCK` 409 (`sku`, `available`), `PRODUCT_HAS_HISTORY`, `DUPLICATE_SKU`, `ORDER_ALREADY_CANCELLED` 409, `NOT_FOUND` 404.

## Postman

Files in `postman/`: `StockFlow.postman_collection.json` and `StockFlow.local.postman_environment.json` (`baseUrl` = `http://localhost:8080`).

> **AI-generated.** These files were written by an AI assistant (Claude) by reading this repo's existing handler and store code; they were not exported from Postman or hand-authored. The assistant ran them with Newman against the seeded docker stack (36 requests, 63 assertions, all passing), but no human has reviewed them. They assume the seed data (product 1 has history, product 10 has 0 stock), so re-seed with `docker compose down -v && docker compose up --build` if results differ.

Import both files in Postman, select the environment, then run the collection top to bottom (some requests save `productId` / `orderId` for later ones). CLI:

```bash
npx newman run postman/StockFlow.postman_collection.json -e postman/StockFlow.local.postman_environment.json
```

## Stack and library choices

| Layer | Used | Why |
|---|---|---|
| HTTP | Go 1.22+ `net/http` `ServeMux` (method + path patterns) | The API is 14 routes; the stdlib router now supports `GET /api/products/{id}`. Gin/Echo/Fiber would add a dependency and their own context type for no gain here. |
| DB access | `pgx/v5` + `pgxpool`, hand-written SQL | The safety of the app is one guarded `UPDATE ... WHERE stock >= n`. Raw SQL keeps that visible and exact; GORM would hide it behind generated queries and make the transaction/locking behaviour harder to audit. |
| Migrations | plain `.sql` files in `backend/migrations`, run by the Postgres image's init hook | Zero tooling to run in 5 minutes. See "What I'd improve". |
| Frontend server state | `@tanstack/react-query` | Replaces hand-rolled fetch/loading/error/abort code. Mutations invalidate `products`, `summary` and `orders`, so summary cards, the product list and the order list refresh after any change with no manual wiring. `keepPreviousData` keeps the table stable while paging or searching. |
| UI | React 19 + hand-written CSS (no component library) | Four screens and two modals. A library (MUI, Radix, shadcn) would be more code and bundle than the app itself. The one thing worth borrowing from one is accessible dialogs; `Modal.tsx` implements focus trap, Escape and focus restore directly (~60 lines). Revisit if the UI grows past this. |
| Fonts | IBM Plex Sans / Mono via Google Fonts | Falls back to system fonts offline. |
| Backend tests | `go test -race`, `testify`, `mockery` v2 | Store tests run against real Postgres (the concurrency guarantees need a real DB). HTTP handler tests use a mockery-generated `MockStore`, so error mapping and validation are tested without a database. |
| Frontend tests | Vitest | Pure-logic tests (validation, formatting, audit text); no React Testing Library yet. |
